# Copilot Instructions for Event Management Portal

## Project Overview

This is a TypeScript monorepo for an Event Management Portal using modern web development practices. The project is currently in migration from JavaScript to TypeScript with plans for frontend modernization.

## Architecture & Tech Stack

### Backend

- **Runtime**: Node.js with Express.js
- **Language**: TypeScript (migrating from JavaScript)
- **Database**: MongoDB with Mongoose ODM
- **Authentication**: Passport.js with JWT tokens
- **File Upload**: Cloudinary for image/media storage
- **Email**: Nodemailer for transactional emails
- **Validation**: Express-validator or Zod
- **Testing**: Jest with supertest
- **Documentation**: OpenAPI/Swagger

### Frontend (Planned)

- **Framework**: Next.js 14+ with App Router
- **Language**: TypeScript
- **Styling**: Tailwind CSS
- **UI Components**: shadcn/ui (primary), Radix UI primitives
- **Icons**: Lucide React (primary), Heroicons (alternative)
- **Forms**: React Hook Form with Zod validation
- **State Management**: Zustand or React Query/TanStack Query
- **Notifications**: react-hot-toast or sonner
- **Charts**: Recharts or Chart.js

### Monorepo Structure

- **Package Manager**: pnpm with workspaces
- **Build Tool**: Turborepo for orchestration
- **Packages**:
  - `@event-management/backend` - Express.js API server
  - `@event-management/frontend` - Next.js application
  - `@event-management/shared` - Shared TypeScript types and utilities
  - `@event-management/ui` - Shared UI components (future)

## Development Guidelines

### Code Quality Standards

- **Type Safety**: 100% TypeScript coverage, no `any` types except for legacy integration
- **Linting**: ESLint with strict TypeScript rules
- **Formatting**: Prettier with consistent configuration
- **Testing**: Minimum 80% code coverage
- **Documentation**: JSDoc for complex functions, README for each package

### API Design Principles

- **RESTful Design**: Follow REST conventions strictly
- **JSON Responses**: All API endpoints return JSON (no server-side rendering)
- **Standardized Format**:

  ```typescript
  // Success Response
  {
    success: true,
    message: string,
    data?: T,
    meta?: { pagination, etc. }
  }

  // Error Response
  {
    success: false,
    message: string,
    error?: string,
    errors?: Record<string, string[]>
  }
  ```

- **HTTP Status Codes**: Use appropriate status codes (200, 201, 400, 401, 403, 404, 500)
- **Input Validation**: Validate all inputs with Zod schemas
- **Error Handling**: Centralized error handling middleware

### Frontend Development Standards

- **Component Structure**: Atomic design principles (atoms, molecules, organisms)
- **UI Components**: Always prefer shadcn/ui components over custom implementations
- **Icons**: Use Lucide React icons exclusively, no emojis in UI
- **Forms**: React Hook Form with Zod validation schemas
- **Styling**: Tailwind CSS with custom design tokens
- **Accessibility**: WCAG 2.1 AA compliance minimum
- **Performance**: Core Web Vitals optimization

### Database & Models

- **Schema Design**: Normalized design with proper relationships
- **Validation**: Mongoose schema validation + application-level validation
- **Indexing**: Proper indexes for query performance
- **Migrations**: Version-controlled schema changes
- **Soft Deletes**: Implement soft deletes for audit trails

### Security Best Practices

- **Authentication**: JWT with refresh tokens
- **Authorization**: Role-based access control (RBAC)
- **Input Sanitization**: Sanitize all user inputs
- **Rate Limiting**: Implement rate limiting on API endpoints

### Code Organization

- **Separation of Concerns**: Clear separation between controllers, services, and models
- **Single Responsibility**: Each function/class has one clear purpose
- **DRY Principle**: Avoid code duplication, create reusable utilities

### Testing Strategy

## Code Examples

### API Controller Pattern

```typescript
export const createEvent = async (
  req: Request<{}, {}, CreateEventRequest>,
  res: Response
): Promise<void> => {
  try {
    const validatedData = createEventSchema.parse(req.body);
    const event = await EventService.create(validatedData, req.user.id);

    res.status(201).json({
      success: true,
      message: 'Event created successfully',
      data: event,
    });
  } catch (error) {
    if (error instanceof ZodError) {
      res.status(400).json({
        success: false,
        message: 'Validation failed',
        errors: formatZodErrors(error),
      });
    } else {
      next(error);
    }
  }
};
```

### Service Layer Pattern

```typescript
class EventService {
  static async create(
    data: CreateEventRequest,
    userId: string
  ): Promise<Event> {
    const session = await mongoose.startSession();
    session.startTransaction();

    try {
      const event = await EventModel.create([{ ...data, createdBy: userId }], {
        session,
      });
      await LogService.create(
        {
          userId,
          action: 'CREATE_EVENT',
          resourceId: event[0]._id,
        },
        { session }
      );

      await session.commitTransaction();
      return event[0];
    } catch (error) {
      await session.abortTransaction();
      throw error;
    } finally {
      session.endSession();
    }
  }
}
```
